# Щоденник — електронний журнал і рейтинг групи

Вебзастосунок (PWA) і сервер для групи: розклад і посилання на пари, домашнє завдання з підтвердженням,
сповіщення, **особисті бали з можливістю підвищення**, **автоматична синхронізація з Google Таблицею**,
статистика й щоденні підсумки прогресу для кожного студента та повна панель адміністратора.
Інтерфейс повністю українською. Сервер сумісний з iOS-застосунком (ті самі `/api/...`).

## Що всередині

```

lib/
  passwords.js         паролі (scrypt), коди скидання
  sheets.js            читання Google-таблиці (публічне посилання / опублікований CSV / сервісний акаунт)
  rating-core.js       розбір таблиці, правила злиття джерел, перевірка підвищення бала, місця
  rating-service.js    запис: міграція, підвищення бала (транзакція), імпорт, синхронізація, конфлікти
  rating-read.js       читання: кабінет студента, статистика, панель і аналітика адміністратора
  rating-routes.js     HTTP-маршрути рейтингу
  stats.js, time.js    статистика з історії змін, межі днів/тижнів за київським часом
  csv.js               розбір CSV
public/                вебзастосунок без збірки
  index.html, css/     дизайн-система (app.css) і стилі розділів
  js/main.js           каркас, маршрути, сеанс
  js/core/             API, стан, компоненти, графіки (SVG), іконки
  js/views/            сторінки студента; js/views/admin/ — панель адміністратора
  schedule.js, rating.js  розбір файлів розкладу й рейтингу (.xls/.xlsx/.csv)
  sw.js, manifest       офлайн-оболонка й push-сповіщення
scripts/dev.js         локальний запуск із тимчасовою базою в пам’яті
scripts/make-admin.js  призначення адміністратора (і пароля) напряму в базі
```

Папка `project/` — окремий проєкт, щоденник його не використовує.

## Запуск

### Локально (без MongoDB Atlas)
```bash
npm install
npm run dev               # тимчасова база в пам’яті, http://localhost:3000
npm run dev -- --demo     # те саме + демо-акаунти й історія за 4 тижні (лише для перевірки)
npm test                  # 40 тестів: логіка, безпека, синхронізація, статистика, API
```
Демо-режим друкує логіни: адміністратор «Адміністратор Демо Тестовий» і студент «Кіянченко Нікіта Олександрович»,
пароль `demo-password-1`. Дані зникають після зупинки.

### Сервер (Render + MongoDB Atlas)
1. MongoDB Atlas → безкоштовний кластер M0 → користувач із паролем → *Network Access* `0.0.0.0/0` → рядок `mongodb+srv://…`.
2. Render: *New → Blueprint* (підхопить `render.yaml`) або *Web Service* з `npm install` / `npm start`.
3. Змінні середовища:

| Змінна | Значення |
|---|---|
| `MONGODB_URI` | рядок підключення Atlas (**обов’язково**) |
| `ADMIN_NAMES` | ПІБ адміністраторів через кому |
| `ADMIN_PASSWORD` | секрет для першої реєстрації під ПІБ адміністратора (без нього ПІБ адміністратора може «зайняти» будь-хто) |
| `VAPID_SUBJECT` | `mailto:` + **реальна** пошта (інакше Apple відхиляє сповіщення) |
| `GOOGLE_SHEET_ID` | ідентифікатор таблиці (за замовчуванням — таблиця групи 101 СПД) |
| `GOOGLE_SHEET_GID` | аркуш (`0` — перший) |
| `GOOGLE_SHEET_GROUP` | назва групи для записів із таблиці (`101 СПД`) |
| `GOOGLE_SHEET_INTERVAL_MS` | як часто перевіряти таблицю (типово 300000 = 5 хв, мінімум 60000) |
| `GOOGLE_SHEET_CSV_URL` | необов’язково: адреса опублікованого CSV замість `GOOGLE_SHEET_ID` |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | необов’язково: ключ сервісного акаунта для **закритої** таблиці |
| `SCORE_MAX` | найбільший бал, до якого студент може підвищити бал з предмета (типово 100) |
| `PROGRESS_HOUR` | година щоденного сповіщення про прогрес за `APP_TZ` (типово 19) |
| `DB_NAME`, `APP_TZ`, `GRADES_DB`, `GRADES_HOUR`, `MAX_DEVICES`, `REQUIRE_DEVICE_APPROVAL`, `JWT_SECRET`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `KEEP_ALIVE` | як і раніше (див. `.env.example`) |

Ключі підпису й VAPID-ключі сервер створює сам і зберігає в MongoDB.

## Акаунти й безпека

- **Вхід за ПІБ і паролем.** Паролі зберігаються як scrypt-хеш. Токен сеансу прив’язаний до пристрою й «версії сеансів»:
  вихід, відв’язування пристрою адміністратором, зміна чи скидання пароля одразу роблять старі токени недійсними.
- **Старі акаунти** (до оновлення без пароля) продовжують працювати на вже прив’язаних пристроях, але одразу після
  відкриття застосунку мусять створити пароль. Вхід такого акаунта з нового пристрою підтверджує адміністратор.
- **Забутий пароль:** адміністратор у «Акаунти й пристрої» натискає «Скинути пароль» і передає студентові одноразовий код
  (діє 24 год). Студент вводить код замість пароля й створює новий.
- **Ролі:** студент, староста / заступник (модерація домашнього, розклад), адміністратор (уся панель). Кожен маршрут
  перевіряє роль на сервері.
- Обмеження частоти: спроби входу (за IP і за акаунтом — блокування на 15 хв після 8 помилок), реєстрації, підвищення балів.

Призначити адміністратора напряму в базі: `MONGODB_URI=… npm run make-admin -- "Прізвище Ім'я По батькові" "пароль"`.

## Бали студента

- Студент бачить свій поточний бал з кожного предмета, попередній бал, зміну, місце з предмета й середнє групи.
- **Підвищення бала** (`POST /api/me/scores/increase`): сервер сам визначає запис студента за акаунтом (поля з тіла
  запиту на кшталт `ratingId` ігноруються), перевіряє, що акаунт прив’язаний адміністратором, має пароль, предмет існує,
  поточний бал наявний, новий бал **строго більший** і не перевищує `SCORE_MAX`. Оновлення атомарне (умова на версію
  запису й поточне значення; на Atlas — у транзакції разом із записом журналу). Зменшити бал студент не може.
- Кожна зміна потрапляє в журнал `ratingHistory`: попередній і новий бал, різниця, предмет, студент, хто змінив, джерело,
  час. Адміністратор бачить усі зміни й може скасувати зміну студента.

## Синхронізація з Google Таблицею

Таблиця групи доступна за посиланням для читання, тому **ключі не потрібні**: сервер читає її CSV через ендпоінт
візуалізації Google (`/gviz/tq?tqx=out:csv`; запасний варіант — `/export?format=csv`). Перевірено на таблиці
`1grET3-MHCkBXqrBrHL1BIiUnAks0Kh3P4MuOijcPykY`: 33 студенти, 8 предметів. Якщо таблицю закриють, сервер покаже
зрозумілу помилку — тоді або знову відкрийте доступ «Усі, хто має посилання — читач», або опублікуйте CSV
(`GOOGLE_SHEET_CSV_URL`), або додайте сервісний акаунт (`GOOGLE_SERVICE_ACCOUNT_JSON`). Сервер у таблицю нічого не пише.

Як працює:
1. Кожні `GOOGLE_SHEET_INTERVAL_MS` (і кнопкою «Синхронізувати зараз») сервер завантажує аркуш, шукає колонку «ПІБ /
   Прізвище», праворуч — предмети; примітки в дужках («староста») і текст у колонках без заголовка зберігаються.
2. Якщо вміст таблиці не змінився (порівняння хешу), нічого не записується.
3. Студенти зіставляються за ПІБ у межах групи (унікальний індекс — дублікатів немає). Нові додаються, змінені бали
   оновлюються за правилами нижче, зміни ПІБ/приміток фіксуються. Студентів, яких немає в таблиці, **не видаляємо** —
   запис деактивується з історією; якщо зникла більша частина таблиці, деактивацію пропускаємо (захист від помилки).
4. Кожен запуск зі змінами чи помилкою записується в історію синхронізацій; панель показує останню вдалу синхронізацію,
   наступну за розкладом, кількість доданих/оновлених записів, помилки й конфлікти.

**Пріоритет джерел (без конфліктів і перезапису новіших даних):**
- Клітинка таблиці, яка не змінилася з минулої синхронізації, нічого не перезаписує — бал, підвищений студентом чи
  виправлений адміністратором, зберігається.
- Змінене значення таблиці, **більше** за поточне, застосовується завжди.
- Змінене значення, **менше** за поточне, застосовується лише тоді, коли поточний бал теж прийшов із таблиці
  (офіційне виправлення). Якщо поточний бал виставив студент чи адміністратор — бал не знижується, а створюється
  **конфлікт**, який адміністратор вирішує на сторінці «Синхронізація» (прийняти значення таблиці або залишити поточне).
- Імпорт файлу адміністратором працює за тими ж правилами.

## Статистика й сповіщення

Стан на будь-який момент відтворюється з журналу змін, тому графіки (дні / тижні / місяці), місце в рейтингу в динаміці,
порівняння з групою і повідомлення на кшталт «Ваш рейтинг з предмета «…» покращився на 8% порівняно з учорашнім днем»
будуються лише з реальних даних. Якщо історії ще недостатньо, застосунок так і пише. Відлік історії починається
з моменту оновлення (наявні бали записуються як «початкові значення»). Раз на день о `PROGRESS_HOUR` студенти з
увімкненими сповіщеннями отримують підсумок прогресу (можна вимкнути в профілі). Повні назви предметів для повідомлень
адміністратор задає в «Рейтинг і групи».

- Сповіщення на iPhone — iOS 16.4+, Safari, запуск із значка на початковому екрані.
- Безкоштовний Render «засинає»; сервер сам себе будить кожні 10 хв (`KEEP_ALIVE=0` вимикає).
- Старий iOS-застосунок працює з наявними сеансами; для входу з нового пристрою йому потрібен пароль (поле `password`
